= Quintessence: plan to v1.0.0
:revdate: 2026-11-15
:toc:

Quintessence is an alpha prototype of a three-layer verifier for Elixir/OTP.
This plan is the execution layer. It does not replace the design documents.
The work packages WP-01 to WP-27 stay in
link:../status/QUINTESSENCE-ROADMAP.adoc[the roadmap]. The milestones M1 to M5
stay in link:../architecture/QUINTESSENCE-IMPLEMENTATION-PLAN.adoc[the
implementation plan]. Where those two documents disagree, this plan decides
the order.

The work that is shared with the sibling verifiers (`atoma`, `Apodeixis.jl`,
`bactrian`, `canonry`, `chancel`) is in the family plan,
`docs/plan/FAMILY-ULTRAPLAN.adoc` in `hyperpolymath/atoma`. IDs F1 to F12 and
waves W0 to W5 come from that plan.

== Definition of v1.0.0

The seven family gates apply. The text below is the Quintessence reading.

[cols="1,4,3",options="header"]
|===
| Gate | Acceptance | Falsifier
| Language boundary | Closed Elixir subset for each layer. The firewall works on expanded code, not on names. | An aliased or imported banned call passes.
| Source connection | Obligations come from the function body and the handler code. No special case for an example. | A body-only mutant keeps the old evidence.
| Semantics | Layer A contracts and termination. Layer B protocol rules for the real handler. Layer C obligations checked, not pattern-matched. | A NIF with an unchecked obligation gets `proved`.
| Replay | Each certificate passes a real checker through ECHIDNA. Level 5 needs both kernels to check the emitted files. | A certificate with a `hole` step is accepted.
| Practical coverage | Three pilots beyond the worked example. | A second project needs engine changes.
| Assurance | Mutants are killed by the full pipeline. The suite runs in CI on pinned tools. | A mutant survives because the gate used a fast mode.
| Release and estate | README, deed and changelog are true. The NIF receipt reproduces on a clean runner. | The receipt differs between two hosts.
|===

Sonnet does the implementation tasks inside each stage from an Opus brief.
Haiku runs the scout pass before each step and does the mechanical edits.
The advisor reviews the close of each stage and each change to a status word.

== What Quintessence takes from the family, and gives

* Takes: the evidence kit (F3), the pin table (F6), the ECHIDNA client (F7),
  Zig checks from `atoma` (F8).
* Gives: the error-code and exit-code contract (`src/core/errors.zig`), the
  suite harness (`assert_case`), the SARIF output. These are candidates for
  the kit.
* Shares with `bactrian`: the actor protocol layer (F9).

== Stop points

* If Q0 cannot make the receipt reproduce, remove the claim of a reproducible
  receipt from the README and the design, then continue.
* If Q1 shows that ECHIDNA cannot check the certificates, stop and review the
  evidence design with the advisor. Do not improve the local Alethe check as a
  substitute.
* Do not start Q4 or Q6 before they are split into parts of size L or smaller.
